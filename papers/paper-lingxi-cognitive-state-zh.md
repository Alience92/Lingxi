# 语义检索与记忆偏置代理状态在个人 Agent 系统中表现出分化的记忆访问模式

**作者**：[Alience]
**单位**：独立研究者

**日期**：2026 年 6 月

---

## 摘要

当前基于 LLM 的 Agent 记忆系统将记忆视为单一维度的资源：片段被存储、按语义相似度检索、注入上下文。我们构建了灵犀（Lingxi），一个个人 Agent 认知架构，包含 2,700+ 条跨四个语义通道（WHAT/FEEL/WHO/WHERE）组织的记忆碎片、一个设备端神经分类器（<50ms 推理）、一个 8 阶段记忆蒸馏管线，以及一个结合全文搜索与向量相似度的检索引擎。在构建该系统的过程中，我们观察到记忆访问可以产生两种显著分化的信号模式：**语义检索**（按查询相似度检索的片段）和**记忆偏置代理状态**（按系统计算的状态向量检索的片段）。我们通过三条收敛的证据线表征了这种分化：（1）memory-bias 嵌入重定向显示 60% 的查询被重新排序，与语义搜索有 93% 的不重叠率；（2）认知偏移检测仅使用 top-5 片段二元组重叠即可识别 96% 的时间窗口注意力转移；（3）一个本地轻量模型（macbert-102M + MLP）以余弦相似度 0.967 预测这些代理状态向量，其标签**从记忆系统统计中自动生成**——不需要任何人工标注或 LLM 标注。序列上下文降低语义搜索质量（相似度从 0.945 降至 0.892）但改善代理状态预测（重叠度从 1.76 提升至 2.40），提示这两种访问模式响应不同的信息处理需求。我们还展示了训练范式的重要性：因果关系的成对分类因结构性过拟合在 0.77 处达到天花板，而代理状态回归通过自举标签移除了外部标注瓶颈。我们的结果表明，有效的个人 Agent 记忆可能得益于多个独立访问机制的并行运作，且代理状态维度可以在本地捕获，无需云端 LLM 调用。代码、实验脚本和训练数据均已公开。

## 1 引言

基于 LLM 的 Agent 的快速发展伴随着记忆系统的同步演进。从简单的对话缓冲区到复杂的检索增强架构（Mem0、Letta/MemGPT、Zep），主导范式始终一致：记忆片段被存储为离散记录，按与当前查询的语义相似度检索，然后注入 Agent 的上下文窗口。这种检索优先的方法产生了强大的工程成果，但它建立在一个 largely 未被审视的隐含假设之上：**所有记忆都是同一种东西**。

在这一假设下，一个事实（"用户使用 TypeScript"）、一个偏好（"用户不喜欢冗余确认"）、一次纠正（"用户纠正了 Agent 删除注释的行为"）和一个决策（"用户选择了 React 而非 Vue"）都被视为同等类型的记忆片段，仅通过语义内容和检索分数加以区分。检索机制——无论是全文搜索、向量余弦相似度还是学习到的注意力——对所有片段类型统一运作。

我们挑战这一假设。通过构建灵犀（Lingxi）——一个不仅建模*用户知道什么*而且建模*用户怎么想*的个人 Agent 认知架构——我们发现 Agent 记忆至少包含两个根本不同的信号维度，且它们几乎完全正交：

- **语义检索信号**：用户当前在谈论什么。由标准的嵌入检索捕获，回答"哪些记忆与这个查询相关？"
- **认知状态信号**：用户当前在想什么——其注意力焦点、关注优先级、认知轨迹。回答"用户此刻的认知状态是什么？"

这两个信号指向记忆空间中几乎不重叠的区域。在我们的实验中，认知状态预测检索的 top-10 片段与语义搜索的重叠仅为 0.68/10——意味着 93% 的检索片段是不同的。这不是更好排序函数的边际改进；这是**认知状态和语义相关性是记忆访问的独立维度**的证据。

这一发现不是来自先验理论推理，而是来自构建完整认知架构的实践挑战。灵犀将记忆片段组织在四个语义通道上（WHAT 用于事实，FEEL 用于纠正和偏好，WHO 用于关系上下文，WHERE 用于文件/项目引用），运行本地 ONNX 神经分类器实现低于 50ms 的推理，实现 8 阶段的 dreaming 管线进行记忆蒸馏，并维护一个带宪法级保护关键片段不可低于最低活性阈值的衰减系统。每个架构决策都为双信号发现可见创造了条件。

我们的贡献有三方面：

1. **第二检索分化信号的证据**：我们提供了定量证据，表明记忆偏置代理状态向量和基于查询的语义检索访问记忆空间中显著不同的区域。在我们的实验设置下，序列上下文降低语义搜索质量但改善代理状态预测，提示两种访问模式有不同的处理需求（§4）。

2. **自举训练方法**：我们展示了代理状态预测模型可以使用从记忆系统统计（memory-bias 加权平均）自动生成的标签进行训练，不需要任何人工标注或 LLM 标注。这移除了此前限制分类方法的外部标注瓶颈（§5）。

3. **本地代理状态预测**：我们展示了一个轻量级本地模型（macbert-102M + MLP，<50ms 推理）可以以余弦相似度 0.967 预测这些代理状态向量，实现连续状态跟踪而无需云端 LLM 调用（§5, §6）。

本文的其余部分组织如下：§2 回顾相关工作；§3 描述使发现成为可能的灵犀架构；§4 展示双信号发现；§5 描述自举方法；§6 报告定量实验；§7 分析先前方法为何失败以及回归为何成功；§8 讨论影响；§9 讨论局限性；§10 总结。

## 2 相关工作

### 2.1 Agent 记忆系统

现代 Agent 记忆领域由检索优先架构主导。Mem0（2024）开创了从对话中提取记忆片段并通过向量相似度检索注入上下文的模式。Letta（前身 MemGPT；Packer 等，2023）引入了虚拟记忆层次结构，将上下文窗口视为有限的资源进行分页管理。Zep（2024）专注于长期记忆提取和事实验证。MemoryBank（Zhong 等，2024）实现了带时间索引的情景记忆。

所有这些系统共享一个共同假设：记忆片段是同质的记录，仅通过内容加以区分。检索——无论是 BM25、余弦相似度还是学习到的注意力——是记忆访问的唯一机制。我们的工作通过证明存在检索无法捕获的正交认知信号维度来挑战这一假设。

Luo 等人（2026）的一项同步综述（已被 ACL 2026 Findings 接收）提出了 LLM Agent 记忆的三阶段演化框架：Storage → Reflection → Experience。他们将"主动探索"和"跨轨迹抽象"识别为 Experience 阶段的前沿机制。我们的认知状态预测可以被视为 Experience 阶段的早期实例——模型从记忆的累积统计结构中学习预测认知状态，而非从显式检索中学习。

### 2.2 记忆内化与主动式 Agent

δ-mem（2026）提出了一个小型相关矩阵，持续压缩交互历史并将结果直接注入注意力层，改变模型处理每个输入的方式。他们的方法证明记忆可以影响超越简单检索的推理，在特定基准上取得 +6.76 分。然而，δ-mem 的矩阵是通用的（跨用户共享），不区分语义和认知维度。

ProAct（Hu 等人，2026）引入了空闲时间计算以实现主动式 Agent 行为，在沉默期间预测用户需求。他们的架构将所需对话轮次减少 14.8%，幻觉率降低 28.1%。ProAct 使用 LLM 推理进行预测，而我们的方法使用本地 <50ms 模型——实现连续认知状态跟踪而非离散预测事件。

HyMem（Zhao 等人，2026）提出了混合记忆架构，根据查询复杂度进行动态检索调度。虽然 HyMem 解决了效率问题，但它没有引入正交于语义检索的认知信号维度。

### 2.3 个性化与用户建模

LLM 系统中的用户个性化主要关注偏好提取和风格适配。这些方法通常建模表面层偏好（编码风格、沟通语气）而非更深层的认知模式。我们的认知状态预测在不同层面运作：它捕获的不是用户偏好什么，而是*用户当前如何思考*——其注意力轨迹、关注优先级以及认知焦点的隐含结构。

MeloTune（Xu，2026）展示了用于音乐策展的设备端认知状态预测，使用 CfC 网络预测 Russell 环形模型上的情感轨迹。虽然架构上相似（本地模型预测连续状态向量），但 MeloTune 在情感域（唤醒/效价）而非认知域（注意力/关注优先级）运作，且不考察与语义检索的正交性。

### 2.4 Agent 系统的小模型

大云端模型旁使用小型本地模型是新兴模式。Voyager（Wang 等人，2023）使用通过自验证代码执行增长的技能库。Reflexion（Shinn 等人，2023）使用存储为记忆的言语强化信号。这些方法将小模型用于特定子任务（代码验证、反思评分），但不用于维护连续的认知状态表示。

我们的工作不同之处在于本地模型（macbert-102M ONNX）不执行离散任务，而是维护用户认知状态的连续表示。该模型在每条用户消息上运行（<50ms 延迟），产生编码用户当前认知位置的 768 维向量——这与任务专用小模型的角色根本不同。

### 2.5 差距总结

| 维度 | 现有工作 | 本文 |
|------|:---:|:---:|
| 正交信号发现 | ✗ | ✓ |
| 自举标签 | ✗ | ✓ |
| 本地认知预测 | 部分（MeloTune，仅情感域） | ✓（认知域） |
| 完整认知架构 | 部分（组件分别存在） | ✓（端到端系统） |
| 训练范式分析 | ✗ | ✓（分类 vs 回归） |

据我们所知，现有工作没有：（1）经验证明认知状态与语义检索信号的正交性；（2）证明认知状态预测可以用自动生成的标签训练；或（3）分析训练范式（分类 vs 回归）如何从根本上决定个人 Agent 记忆是否可以被学习。

## 3 系统架构：灵犀

灵犀是一个个人 Agent 认知架构，构建为 TypeScript/Node.js 系统，使用 SQLite 存储，设计为通过 hooks 和 MCP（Model Context Protocol）与编码 Agent（Claude Code、OpenClaw、Codex）并行运行。架构由五个互连组件组成。每个组件独立设计，但共同创造了双信号发现成为可能的条件。

### 3.1 四通道碎片化

记忆片段组织在四个语义通道上，每个通道捕获用户-Agent 交互的不同维度：

- **WHAT**：事实知识、技术决策、实现细节、任务描述
- **FEEL**：用户纠正、偏好、情感信号、质量标准
- **WHO**：关系上下文、信任级别、协作模式、角色信息
- **WHERE**：文件路径、项目引用、空间/时间锚点、代码库位置

每个片段携带来自一个或多个通道的锚点及关联权重。例如，关于"login.ts 中的 JWT 配置"的片段可能在 WHAT（技术事实）、WHERE（文件引用）和 FEEL（如果用户对此表达了偏好）中有锚点。这种多通道结构对双信号发现至关重要：没有通道分离，FEEL 通道的认知信号会被 WHAT 通道的语义内容稀释。

碎片化过程使用轻量级提取管线从对话记录中提取结构化片段。每个片段获得唯一 ID、带权重的通道锚点、摘要和时间元数据。截至撰写时，系统已在约 130 个会话中累积 2,700+ 条活跃片段。

### 3.2 本地神经分类器（灵眸）

灵眸（Lingmou）是一个编译为 ONNX 格式的 macbert-102M 模型，用于本地推理。其主要功能是通道分类——将每个输入片段分配到四个通道之一（WHAT/FEEL/WHO/WHERE），延迟低于 50ms。该模型完全在设备端运行，不需要云端 API 调用。

灵眸的存在建立了关键的架构属性：**系统有一个快速的本地认知处理层，独立于云端 LLM 运行**。正是这种分离使认知状态预测能够在每条用户消息上连续运行，而不会给 Agent 的响应时间增加有意义的延迟。

除了通道分类，灵眸还充当 memory-bias 计算和认知状态预测的编码器（见 §5）。分类通道的同一个模型也提取用于所有下游认知处理的 768 维嵌入。

### 3.3 记忆蒸馏管线（灵枢）

灵枢（Lingshu）是一个 8 阶段 dreaming 管线，将原始片段处理为高阶结构：

1. **累积**：来自对话的原始片段
2. **模式检测**：识别跨片段的反复主题
3. **冲突解决**：检测和解决矛盾片段
4. **规则提取**：从片段模式导出蒸馏规则
5. **权重调整**：基于累积证据更新片段权重
6. **衰减应用**：对不活跃片段应用基于时间的衰减
7. **整合**：合并冗余片段
8. **宪法保护**：保护关键片段免于衰减

蒸馏管线产出 16 条 L0（宪法级）规则，每条都有显式的源片段 ID。这些规则代表系统对用户偏好和约束的最高置信度信念。管线周期性运行，不在每条消息上运行，在实时认知处理（灵眸）和长期认知整合（灵枢）之间创造时间分离。

### 3.4 衰减与检索系统

衰减系统实现新颖性自适应阶梯机制。每个片段携带一个 `decayScore`，随时间下降但被以下因素提升：
- 直接用户交互（召回事件）
- 与高权重 FEEL 信号的关联
- 与 L0 规则的连接

宪法级片段（连接到 L0 规则）获得衰减保护，永远不会低于最低活性阈值。新颖性因子根据最近交互的多样性调整衰减率——新颖交互模式减缓衰减，重复模式加速衰减。

检索引擎结合三种机制：
- **全文搜索**（SQLite FTS5）用于关键词匹配
- **向量余弦相似度**（1536 维嵌入）用于语义匹配
- **MMR（最大边际相关性）**用于 top-k 结果中的多样性
- **显式知识边**（corrected_by, distilled_from）用于因果关联

显式知识边是在 Phase 3 实验（§6.1）证明在真实生产检索器基线上有 +27% 检索改进后添加的。这些边编码语义相似度无法捕获的因果关系——例如用户纠正与其纠正的行为之间的连接。

### 3.5 多层上下文注入

在会话开始时，系统将四层记忆注入 Agent 的上下文：

| 层 | 内容 | 来源 |
|----|------|------|
| 1 | 宪法规则（铁律） | L0 蒸馏规则 |
| 2 | 用户偏好事实 | 蒸馏摘要 |
| 3 | 检索到的记忆片段 | Prefetch（FTS5 + 向量 + 边） |
| 4 | 认知状态叙述 | 认知状态预测模型 |

第 4 层是最新添加的（本工作）。与注入*内容*（具体事实、规则或片段）的第 1-3 层不同，第 4 层注入*认知上下文*——对用户当前注意力焦点和关注优先级的描述。这种区分对我们的双信号发现至关重要。

### 3.6 架构作为发现条件

双信号发现不是从单个组件中产生的，而是来自多个组件的交互：

- **四通道结构**使得分离 WHAT（语义）信号和 FEEL（认知）信号成为可能。没有通道分离，memory-bias 实验不会揭示差异化效应。
- **本地 ONNX 模型**使连续认知状态计算可行（每条消息 <50ms）。没有快速本地推理，认知状态在每条消息上计算太昂贵。
- **衰减系统**给片段赋予差异化权重，使 memory-bias 加权平均能产生有意义的认知状态向量。没有权重区分，所有片段贡献相等，认知信号将是均匀噪声。
- **多层注入**为认知状态作为独立于内容检索的单独层提供了集成点。

每个架构决策都由工程关注驱动，而非关于双信号的先验假设。发现从系统行为中涌现，而非从系统设计中。这是工作的优势——发现对架构变化是鲁棒的，因为它不是为了产生特定结果而设计的。

## 4 发现：双信号记忆

双信号记忆的发现通过三条收敛的实验线涌现。我们按时间顺序呈现，因为每个实验启发了下一个。

### 4.1 Memory-Bias 嵌入重定向（实验 1）

**假设**：如果记忆被应用为查询表示的偏置而非检索到的上下文，它可能将检索重定向到记忆空间的不同区域——捕获认知相关性而非语义相关性。

**方法**：我们计算"认知背景向量"为所有 2,674 条活跃片段嵌入的加权平均，权重为 `decayScore × (1 + FEEL_weight/255)`。对每个查询，计算偏置查询向量：`biased_query = raw_query + α × cognitive_background`，然后比较 `raw_query` 与 `biased_query` 的 top-5 检索结果。

**结果**（α = 0.2，10 个查询）：

| 指标 | 值 |
|------|-----|
| 平均重叠（top-5） | 1.8 / 5 |
| 平均 biased-only 片段 | 3.2 / 5 |
| 完全重定向（重叠 ≤ 1） | 6/10 查询 |

**多样性测试**：为排除 popularity bias（相同高权重片段出现在每个 biased 结果中），我们计算了所有 10 个查询的 biased-only 片段重叠。结果是 **0% 重叠**——没有片段在一个以上的查询中作为 biased-only 出现。这证实了 memory-bias 产生查询特异性重定向，而非广播热门片段。

**解释**：Memory-bias 改变的是*查询如何看到记忆*，而非*哪些记忆匹配查询*。偏置查询进入向量空间的不同区域，因为认知背景偏移了查询的方向。这是认知状态和语义内容可以产生不同记忆访问模式的第一个证据。

### 4.2 认知背景正交性（实验 2）

**假设**：认知背景信号捕获与基于时间的近度信号不同的信息。如果相同的片段按"最重要"（认知权重）vs"最近"（时间近度）排序，重叠应该很低。

**方法**：我们为相同时间窗口计算两个 top-5 片段集：
- **认知 top-5**：按 FEEL weight × decayScore 排序的片段（认知重要性）
- **近度 top-5**：按创建时间排序的片段（最近）

我们测量两个集合摘要之间的二元组重叠。

**结果**：

| 比较 | 二元组重叠 |
|------|:--:|
| 认知 top-5 vs 近度 top-5 | **5.3%** |

**解释**："对用户最重要的"和"用户最近讨论的"是几乎不重叠的信号。基于规则的方法（近度）产出"用户一直在讨论模型训练"。认知方法（权重 × 衰减）产出"用户持续关心错误纠正机制和安全边界"。两者都是有效描述，但指向完全不同的记忆区域。

### 4.3 认知偏移检测（实验 3）

**假设**：如果认知状态是随时间变化的持续信号，那么比较不同时间点的认知状态应该检测到用户注意力的真实转移。

**方法**：对每个会话，我们计算当前 7 天窗口和之前 7-14 天窗口按认知权重的 top-5 片段。测量两个 top-5 集合之间的二元组重叠，计算偏移率：`offset = 1 - overlap`。

**结果**（测试案例）：

| 窗口 | Top-5 内容 |
|------|-----------|
| 当前 7 天 | 代码修复、架构调整、技术实现 |
| 之前 7-14 天 | AGI 重新定义、产品定位、论文规划 |
| **偏移率** | **96%** |

**解释**：系统检测到真实的认知相变——用户从战略思考转向实施工作。这不是记忆检索结果；它是系统关于*用户认知状态如何变化*的自身判断。偏移信号使 Agent 能够调整行为策略：处于实施阶段的用户需要与战略阶段用户不同的支持。

### 4.4 收敛：三个实验，一个发现

上述三个实验收敛于单一结论：

```
语义检索：    查询 → 向量相似度 → 片段
              "用户在谈论什么？"

认知感知：    查询 + 记忆状态 → 偏置表示 → 不同片段
              "用户在想什么？"
```

这不是两种检索策略。它们是 Agent 与用户记忆关联的两种不同方式：
- 语义检索将记忆视为可搜索的**图书馆**。
- 认知感知将记忆视为改变 Agent 如何看待当前输入的**透镜**。

语义和认知检索结果之间 93% 的不重叠（§4.1）、认知和近度信号之间 5.3% 的重叠（§4.2）、以及认知相变的检测（§4.3）都指向同一结论：**认知状态是独立于语义内容存在的信息维度，不能仅通过检索捕获。**

## 5 方法：自举认知状态预测

双信号的发现提出了一个实践问题：认知状态能否被足够高效地预测以在每条用户消息上运行？memory-bias 计算（2,674 个嵌入的加权平均）对实时使用来说太昂贵。我们需要一个模型，仅从用户消息就能在 50ms 内近似认知状态向量。

### 5.1 训练范式：分类 vs 回归

我们的初始方法遵循记忆相关学习任务的标准模式：**成对分类**。我们在 macbert-102M 上训练一个投影层来判断两个片段是否有因果关系，使用 1,130 个来自用户纠正、确认、决策和蒸馏规则的标记对。模型达到正相似度（pos）0.77。

然后我们尝试了五种方法来突破 0.77：

| 方法 | 数据扩展策略 | 结果 |
|------|------------|------|
| 共现 | 同会话片段对（8,369 对） | pos 0.77 → **0.66** |
| LLM 合成 | DeepSeek 因果评分（1,446 对） | pos 0.77 → **0.63** |
| 片段链接 | LLM 生成的链接（1,548 对） | pos 0.77 → **0.38** |
| 三元组损失 | 困难负例挖掘（无新数据） | pos 0.77 → **0.76** |
| 温度缩放 | 推理阈值调优 | pos 0.77 → **无变化** |

五种方法全部失败。模式清晰：**没有外部信号能改善模型对行为因果的判断**。

通过桶评估的**根因诊断**揭示 0.77 分数是结构性过拟合的产物。当我们按标签来源拆分训练数据：

| 桶 | 标签来源 | 数据 | pos | 交叉泛化 |
|----|---------|:----:|:---:|---------|
| distilled_rule | 模板规则 | 64 | 0.686 | 在其他桶上失败 |
| existing | 用户纠正 | 537 | 0.463 | 在其他桶上失败 |
| session_replay | 行为重放 | 302 | 0.283 | 在 existing 桶上 pos 0.075 |

session_replay 模型在 existing 桶上的泛化仅为 pos 0.075——本质上是随机的。模型没有在学习统一的因果判断能力；它在记忆特定于每种标签类型的模式。

**范式转换**：我们识别出根本问题不是数据量或模型容量，而是**训练目标错位**。成对分类要求模型做外部判断（"这两个片段有因果关系吗？"）。这需要来自模型外部的真值标签——因此 perpetually 存在数据瓶颈。

认知状态回归问的是根本不同的问题："给定这条用户消息，用户的认知状态是什么？"答案是连续向量（认知状态向量），标签可以**从记忆系统自身的统计中自动生成**。

### 5.2 自举标签生成

关键洞察是记忆系统已经计算了认知状态的代理：memory-bias 加权平均向量。对于任何会话中的任何用户消息，我们可以通过以下方式计算该时刻认知状态*应该是什么*：

1. 取该消息之前最近的 20 条片段
2. 通过 macbert 计算它们的嵌入
3. 对每个嵌入加权：`通道系数 × 近因衰减 × decayScore × 锚点权重`
4. 平均产生 768 维认知状态向量

这个向量代表记忆系统自身权重机制计算的"用户此刻在认知上关注什么"。它充当认知状态预测模型的训练标签。

**关键属性**：这个标签生成不需要人工标注，不需要 LLM API 调用。它是从记忆系统现有数据结构的确定性计算。每个对话轮次自动产生一个训练样本。

从 130 个会话（每个约 13 轮），我们获得了 1,477 个带自动生成标签的训练样本。在任何阶段都没有执行手动标注。

### 5.3 模型架构

认知状态预测模型包括：

- **编码器**：macbert-102M（预训练中文 BERT，102M 参数）
- **投影**：三层 MLP（768 → 512 → 512 → 768）
- **输出**：L2 归一化的 768 维认知状态向量
- **损失**：预测向量和标签向量之间的 MSE
- **输入**：用户消息文本，可选地与前 2 条消息拼接以提供序列上下文

模型作为 ONNX 在设备端运行，每次推理时间低于 50ms。

### 5.4 序列上下文效应

当我们比较单条消息输入 vs 3 条消息序列输入时，出现了一个令人惊讶的发现：

| 指标 | 单条消息 | 3 条消息序列 | 效应 |
|------|:----:|:----:|:----:|
| 认知状态预测（余弦相似度） | 0.961 | **0.967** | +0.006 ↑ |
| 预测 vs 实际重叠（top-10） | 1.76 | **2.40** | +36% ↑ |
| 查询嵌入相似度 | 0.945 | **0.892** | -0.053 ↓ |

序列上下文**改善**认知状态预测但**降低**语义搜索质量。这不是巧合——它是根本不同的信息处理需求的证据：

- **语义搜索**需要精确、聚焦的查询。添加上下文稀释了查询信号。
- **认知感知**需要上下文模式。单条消息可能是离群值；三条消息揭示轨迹。

在相同输入操作下两个信号之间的这种反向关系是它们是不同处理范式的最强证据，而非应用于相同底层信号的不同排序策略。

## 6 实验

### 6.1 关联矩阵消融（Phase 3）

在双信号发现之前，我们进行了系统消融以测试基于图的记忆关联是否能超越标准语义搜索改进检索。

**设置**：我们在片段之间构建四种类型的边：
- `co_occurred`：同会话共现（1,997 条边）
- `semantic`：向量余弦 > 0.7（2,000 条边）
- `corrected_by`：FEEL 纠正 → WHAT 行为（200 条边）
- `distilled_from`：片段 → 源规则（58 条边）

**消融条件**（渐进添加）：

| 条件 | 组件 | 平均召回 | vs 基线 |
|------|------|:----:|:----:|
| A（基线） | LIKE 关键词搜索 | 2.1 | — |
| B | A + corrected_by + distilled_from | 5.0 | +138% |
| C | B + semantic 边 | 6.9 | +228% |
| D | C + 1-hop 传播 | 9.0 | +328% |

**用真实基线修正**：当条件 A 被替换为生产检索器（FTS5 + 向量 + MMR）：

| 条件 | 平均召回 | vs 真实基线 |
|------|:----:|:----:|
| A（FTS5+MMR） | 2.5 | — |
| B（+显式边） | 3.2 | **+27%** |
| C（+语义） | 3.2 | **+0%** |
| D（+传播） | 3.2 | **+0%** |

**关键发现**：
- 显式知识边（corrected_by + distilled_from）在真实检索器上提供真正的 +27% 改进
- 语义边和图传播在真实检索器上提供零改进——检索器已经捕获了语义边编码的内容
- 边密度（258 条知识边 vs 2,700+ 片段）太低，传播无法增加价值
- **结论**：基于图的关联不能替代检索；显式因果边是补充

### 6.2 认知状态回归

**设置**：在 1,477 个自动标记样本上训练。80/20 训练/验证集划分。在留-out 会话上评估（跨会话泛化）。

**主要结果**：

| 指标 | 值 |
|------|-----|
| 验证集余弦相似度 | **0.967** |
| 验证集 MSE | 0.000101 |
| 训练样本 | 1,477 |
| 标签生成成本 | 零（自动） |

**跨会话检索评估**：

| 检索方法 | 平均最大相似度 |
|---------|:----:|
| 原始查询嵌入 | 0.8921 |
| 预测认知状态 | **0.9587** |
| 实际 memory-bias 状态（上界） | 0.9635 |

**Top-10 重叠分析**（越低 = 信号越独立）：

| 比较 | 重叠 / 10 |
|------|:----:|
| 查询 vs 预测状态 | **0.48** |
| 查询 vs 实际状态 | 1.10 |
| 预测 vs 实际状态 | 1.76 |

**解释**：预测的认知状态检索的片段与语义搜索 95% 不同。预测状态比原始查询（0.8921）更接近实际认知状态（0.9587），证实认知感知捕获了语义搜索遗漏的信息。预测（0.9587）和上界（0.9635）之间的差距仅为 0.0048——模型几乎达到了统计标签能表达的极限。

### 6.3 训练范式对比

为隔离训练目标的效应，我们在相同基础模型（macbert-102M）和数据源（记忆系统统计）上比较了成对分类和认知状态回归：

| 方面 | 成对分类 | 认知状态回归 |
|------|:----:|:----:|
| 训练目标 | 二分类："有因果吗？" | 连续："什么认知状态？" |
| 标签来源 | 人工定义规则 + 纠正信号 | 自动从记忆统计 |
| 数据量 | 1,130 对（瓶颈） | 1,477 样本（自动扩展） |
| 最佳可达分数 | pos 0.77（结构天花板） | cosine 0.967 |
| 数据扩展尝试 | 5 种方法，全部失败 | 不需要 |
| 交叉泛化 | 桶间失败 | 跨会话一致 |
| 推理成本 | <50ms | <50ms |

从分类到回归的范式转换移除了外部标注瓶颈。分类需要外部真值（对行为因果来说稀缺且噪声大）。回归只需要统计标签（记忆系统在正常运作中自动产生），但统计标签本身的质量成为新的瓶颈。

### 6.4 模型容量检查

我们通过将 macbert-102M（102M 参数，768 维）替换为 chinese-roberta-wwm-ext-large（340M 参数，1024 维）来测试 0.967 结果是否受模型容量限制：

| 指标 | macbert-102M | roberta-340M | Δ |
|------|:----:|:----:|:----:|
| 余弦相似度 | 0.967 | 0.969 | +0.002 |
| 推理时间 | <50ms | ~150ms | +200% |

3× 更大的模型以 3× 延迟换取可忽略的改进（+0.002 余弦）。这证实 0.967 结果不受模型容量限制——macbert-102M 对认知状态预测足够了。剩余差距（0.967 vs 0.9635 上界）可能源于统计标签的固有噪声，而非模型限制。

### 6.5 行为验证：检索通道分布

离线评估的一个关键缺口是：认知状态信号是否在检索中产生了*行为上有意义*的差异——而不仅仅是统计上不同的结果。为了验证这一点，我们对来自真实会话 transcript 的 28 条历史用户查询进行了受控对比。

**设置**：对每条查询，我们对包含 500 条活跃片段（含通道标注）的池运行两种检索方法：
- **语义检索**：原始查询 embedding → 余弦相似度 → top-10 片段
- **认知检索**：预测认知状态向量 → 余弦相似度 → top-10 片段

我们测量了行为相关性的三个维度：（1）两种方法之间的检索重叠度，（2）FEEL 通道片段占比（编码用户约束的纠正/偏好片段），（3）FEEL 片段权重（系统对约束重要性的估计）。

**结果**：

| 指标 | 语义检索 | 认知检索 | 比率 |
|--------|:----:|:----:|:----:|
| top-10 中 FEEL 片段占比 | 60.7% | **90.0%** | **1.48×** |
| FEEL 总权重 | 13,900 | **20,610** | **1.48×** |
| 平均 top-10 重叠 | — | — | **0.9 / 10** |
| 零重叠查询数 | — | — | **13 / 28 (46.4%)** |
| 平均片段年龄（天） | 8.9 | **8.2** | — |

**分析**：认知检索系统地比语义搜索检索到更多与约束相关的片段。1.48× 的 FEEL 权重比表明这些不是随机附加片段，而是更高重要性的片段——系统因用户纠正、确认和重复交互而为其分配了更高权重的片段。每条查询，认知检索平均多找回 240 个 FEEL 权重单位的约束信息，这些是语义搜索完全遗漏的。

46.4% 的零重叠率证实近半查询在两种方法间产生了*完全不交集*的 top-10 结果。这不是部分互补——对相当部分查询而言是完全独立。认知检索偏离语义检索时，是完全偏离。

时间深度结果（8.2 vs 8.9 天）表明认知检索偏好稍新的片段——用户*当前*的约束和纠正，而非较早的。这与衰减加权认知状态标签的设计一致：近期高权重 FEEL 片段主导状态向量，而具有相似语义内容的较早片段已经衰减。

**解读**：这些结果确认了代理状态向量产生了与查询 embedding 系统性不同的检索行为，且这种分化与系统自身对约束重要性（FEEL 通道）的加权一致。然而需要注意：FEEL 权重参与了训练标签的构造（§5.2），因此模型偏向 FEEL 片段是标签生成机制的预期结果，而非独立发现。这种检索分化是否转化为真实交互中 Agent 行为的改善，仍需受控行为实验和外部验证——如人工相关性判断或用户纠正率测量。当前结果展示的是*在系统代理定义下的检索行为分化*，而非*认知状态感知作为独立验证的构念*。

### 6.6 定量结果总结

| 实验 | 关键指标 | 结果 | 解释 |
|------|---------|------|------|
| Memory-bias 重定向 | 查询重排率 | 60% | 记忆改变查询视角 |
| 多样性测试 | Biased-only 重叠 | 0% | 非 popularity bias |
| 认知偏移 | 时间偏移检测 | 96% | 认知状态随时间变化 |

| 显式知识边 | 检索改进 | +27% | 因果边补充检索 |
| 语义边 | 检索改进 | +0% | 与检索器冗余 |
| 图传播 | 检索改进 | +0% | 无结构优势 |
| 认知状态预测 | 余弦相似度 | 0.967 | 高精度本地预测 |

## 7 分析

### 7.1 为什么分类失败

五次失败的数据扩展尝试（§5.1）不仅仅是负面结果——它们揭示了将分类范式应用于行为因果的结构性约束。

**外部判断问题**：成对分类要求模型回答"片段 A 和 B 有因果关系吗？"这个问题没有普遍正确的答案——"正确"答案取决于特定用户的行为模式，而这些模式不仅编码在片段文本中。例如：

```
片段 A："用户纠正了 Agent 删除注释的行为"
片段 B："用户修改了 login.ts 配置"

LLM 判断：弱关系（2/5）
  — 从世界知识看，纠正注释和修改文件是独立的。
行为因果：强关系（4/5）
  — 用户的行为模式在时间和因果上连接了这些事件。
```

LLM 校准测试显示 LLM 因果判断与系统行为因果标签之间仅有 **10% 一致**。这不是因为 LLM 错了——而是因为 LLM 回答的是不同的问题。LLM 判断"客观逻辑因果"；系统需要"用户特异性行为链接"。

**结构性过拟合机制**：当在 1,130 对混合标签来源的数据上训练时，模型没有学习统一的因果判断能力。相反，它学习桶特异性模式：
- distilled_rule 桶（0.686）：学习模板匹配模式
- existing 桶（0.463）：学习纠正信号模式
- session_replay 桶（0.283）：学习虚假共现模式

交叉泛化矩阵显示这些模式是互斥的：在一个桶上训练的模型在其他桶上失败（session_replay → existing 的 pos 为 0.075）。0.77 的总分是三种不可迁移能力的加权平均，而非单一连贯能力。

### 7.2 为什么回归成功

认知状态回归在分类失败的地方成功，因为训练目标根本不同：

**分类问**："这两个特定片段之间有关系吗？"
- 需要外部真值（来自用户行为的标签）
- 标签稀疏、有噪声、桶特异性
- 模型学习区分，而非表示
- 数据是瓶颈

**回归问**："给定这条消息，用户的认知状态是什么？"
- 标签从记忆系统统计计算
- 标签密集、自动、每个轮次可用
- 模型学习表示认知位置
- 数据不是瓶颈

关键区别是回归标签来自**系统内部**（记忆统计），而分类标签来自**系统外部**（用户纠正、LLM 判断）。内部标签可以随使用扩展；外部标签不能。

这是**自举属性**：记忆系统在正常运作的副产品中产生自己的训练信号。每个对话轮次产生一个训练样本（该时刻的认知状态向量）。随着使用增加，训练集自动增长，模型自动改善。没有标注管线，没有 LLM 调用，没有人工干预。

### 7.3 正交性作为架构洞察

认知状态和语义检索之间 93% 的不重叠不仅仅是经验观察——它对 Agent 记忆系统应如何设计有架构含义。

**单维度系统**：所有现有 Agent 记忆系统（Mem0、Letta、Zep、MemGPT）在单一维度上运作：语义相关性。片段被存储、按相似度检索、作为上下文注入。系统有一种访问记忆的方式。

**双维度系统**：我们的结果表明有效的个人 Agent 记忆至少需要两个独立的访问机制：
1. **语义检索**："找到与这个查询相关的记忆"（现有方法）
2. **认知感知**："用户此刻的认知状态是什么？"（本工作）

这两种机制产生几乎不重叠的结果。只做语义检索的 Agent 完全错过了认知维度。只做认知感知的 Agent 缺乏回答具体问题的精度。

**透镜 vs 图书馆隐喻**：语义检索将记忆视为图书馆——你搜索特定书籍。认知感知将记忆视为透镜——它改变你看到一切的方式，而非仅你找到的东西。最优的 Agent 记忆系统提供两者：用于具体查询的图书馆和用于认知上下文的透镜。

### 7.4 序列上下文作为诊断工具

序列上下文实验（§5.4）为区分两个信号维度提供了干净的诊断：

```
如果添加上下文改善了性能 → 认知信号
如果添加上下文降低了性能 → 语义信号
```

这个简单测试可以应用于任何记忆访问机制以确定它在哪个维度上运作。它还暗示了一个设计原则：**认知处理受益于上下文扩展；语义处理受益于上下文聚焦。** 试图用相同上下文窗口同时做两者的系统面临固有的权衡。

### 7.5 对 Agent 架构的启示

双信号发现对 Agent 记忆应如何结构化有具体启示：

1. **分离信号**：认知状态不应从与语义检索相同的机制计算。它们需要不同的模型、不同的训练目标、不同的集成点。

2. **不同地注入**：语义检索结果应作为内容注入（"这里是相关事实"）。认知状态应作为上下文注入（"这里是用户当前的认知位置"）。这需要不同的提示格式和 Agent 上下文中的不同位置。

3. **本地 vs 云端**：语义检索可以使用云端嵌入 API（延迟可容忍）。认知状态预测应在本地运行（<50ms），因为它在每条消息上运作，不能增加响应延迟。

4. **连续 vs 离散**：语义检索由查询触发（离散事件）。认知状态应连续维护（每条消息更新），因为用户的认知状态随每次交互变化。

## 8 讨论

### 8.1 从记忆检索到认知感知

Agent 记忆的主导范式一直是检索：存储片段、按相似度检索、注入上下文。这种范式将记忆视为外部资源——Agent 在需要时查阅的东西。我们的结果暗示了一种互补范式：**认知感知**——记忆作为持续塑造 Agent 如何处理每个输入的内部状态。

在认知感知中，Agent 不"检索关于用户的记忆"。Agent 对当前输入的处理*已经被*其对用户认知状态的模型塑造。认知状态向量不是待查阅的事实集；它是所有信息被解读的透镜。

这更接近人类记忆的工作方式。一个人在每次交互前不"检索"对朋友偏好的了解。其对朋友的模型持续活跃，塑造其如何解读每个词句和姿态。检索范式通过注入相关事实来近似这一点；认知感知范式试图复现持续塑造效应。

### 8.2 自举循环

自举属性（§5.2, §7.2）有超越这个特定系统的影响。任何维护内容加权统计的记忆系统都可以为认知状态模型生成训练标签。要求是：

1. 片段有权重（相关性、近度、重要性）
2. 权重随时间变化（通过衰减、强化或整合）
3. 系统可以计算片段嵌入的加权平均

这些要求被大多数复杂记忆系统满足，不仅限于灵犀。自举方法可以应用于 Mem0、Letta 或任何维护片段级统计的系统。

自举循环创造**良性循环**：更多使用 → 更多训练数据 → 更好认知预测 → 更有用认知注入 → 更有效 Agent 行为 → 更多使用。这种自我强化循环与需要外部标注或手动偏好配置的系统有质的不同。

### 8.3 与主动式 Agent 行为的关系

ProAct（Hu 等人，2026）证明 Agent 可以从在空闲时间预测用户需求中获益。他们的方法使用 LLM 推理进行预测，准确但昂贵。我们的认知状态预测模型提供了更便宜的替代：<50ms 本地模型持续跟踪用户的认知轨迹。

组合是有前景的：使用本地认知状态模型进行连续跟踪（快、免费、始终在线），使用 LLM 推理在认知状态模型检测到机会时进行特定预测任务（例如，认知偏移超过阈值，表明用户已转向新关注点）。

### 8.4 隐私启示

完全在设备端运行的认知状态预测有区别于云端记忆系统的隐私含义。认知状态向量永不离开设备——它从本地嵌入计算，由本地模型计算，为本地使用计算。这与将用户对话发送到云端 API 进行记忆提取和检索的系统有质的不同。

对于关注隐私的用户，认知感知范式提供了在不将用户认知暴露给云基础设施的情况下实现个性化 Agent 行为的路径。权衡是本地模型不如云端模型强大——但我们的结果（余弦 0.967）表明对于这个特定任务差距很小。

### 8.5 走向 Agent 认知架构

灵犀系统证明个人 Agent 的完整认知架构在当前技术下是可行的：本地神经模型用于快速处理，SQLite 用于零维护存储，基于 hook 的集成用于跨平台兼容。双信号发现从这个架构中涌现，而非从先验假设——暗示构建完整系统可以揭示组件级分析无法揭示的洞察。

从"有记忆的 Agent"到"有认知的 Agent"的路径需要比更好检索更多的东西。它需要一个独立的信号维度，捕获的不是用户说了什么而是用户如何思考。我们的结果显示这个维度存在、可以被测量、可以在本地预测、且正交于现有系统已经捕获的语义维度。

## 9 局限性

### 9.1 单用户评估

本文所有实验都在单个深度用户的数据上进行（2,700+ 片段，130+ 会话，数月的日常使用）。虽然这种深度为机制发现提供了丰富数据，但它没有建立泛化性。正交信号结构可能特定于这个用户的交互模式、领域或认知风格。

我们没有在额外真实用户上进行评估。自举标签生成理论上适用于任何用户（它只需要片段权重和嵌入），但在声称泛化性之前需要跨用户的经验验证。合成用户实验（通过 LLM 生成不同交互模式的虚拟用户）可以提供初步泛化证据，但不能替代真实多用户评估。

### 9.2 无端到端行为验证

我们证明了认知状态向量可以被高精度预测（余弦 0.967）且它们正交于语义检索（93% 不重叠）。然而，我们尚未验证将预测认知状态注入 Agent 推理过程*以可测量的更好方式改变 Agent 行为*。

认知状态向量已集成到系统的上下文注入管线中（§3.5 的第 4 层），但比较有/无认知状态注入的 Agent 输出质量的受控实验尚未完成。这是一个关键缺口：证明信号存在是必要但不充分的，以证明它有用。

### 9.3 统计标签作为近似真值

认知状态回归的训练标签从 memory-bias 加权平均生成——对片段嵌入和权重的统计计算。这些标签在任何绝对意义上都不是"真值"认知状态。它们是记忆系统基于其权重机制对认知状态应该是什么的自身估计。

这创造了潜在循环性：模型学习预测统计标签，统计标签从模型最终将增强的同一记忆系统计算。如果权重机制有系统性偏差，模型将学习并复现这些偏差。

在当前阶段我们将此视为特性而非缺陷——目标是学习记忆系统自身的认知表示，而非外部真值。然而，对于需要与人类认知状态判断对齐的应用，外部验证是必要的。

### 9.4 注入机制未优化

认知状态向量目前作为文本描述（预测认知状态的自然语言摘要）注入 Agent 上下文。这是将 768 维向量有损压缩为人类可读文本。更直接的注入机制——如 LLM 输入表示的嵌入级偏置——可能捕获更多认知信号。

由于 API 限制（云端 LLM 提供者不暴露嵌入级控制），我们在本工作中没有探索嵌入级注入。这代表我们当前实现和认知状态注入理论能力之间的潜在显著差距。

### 9.5 时间范围

系统已活跃使用数月，但认知状态预测模型在数据的单个快照上训练。我们没有评估模型在更长时间尺度（数月到数年）上用户认知模式如何演变时的表现。衰减系统旨在处理这一点，但预测模型跟踪长期认知演变的能力尚未验证。

---

## 10 结论

我们提出了灵犀（Lingxi），一个个人 Agent 认知架构，并通过其构建发现了 Agent 记忆包含两个正交的信号维度：语义检索（用户在说什么）和认知状态感知（用户在想什么）。我们通过三条收敛的实验线验证了这一发现：memory-bias 重定向显示 60% 的查询被认知状态重新排序，与语义搜索有 93% 的不重叠；认知偏移检测识别 96% 的时间窗口注意力转移；认知状态回归以自动生成的标签达到余弦相似度 0.967。

序列上下文改善代理状态预测但降低语义搜索质量的观察提示这两种访问模式有不同的处理需求，而不仅仅是应用于相同底层信号的不同排序策略。自举标签生成移除了限制先前分类方法的外部标注瓶颈，展示了代理状态模型可以从记忆系统自身的统计输出中训练而无需外部标注。

我们的结果暗示有效的个人 Agent 记忆至少需要两个独立运作的处理机制：用于内容特异性记忆访问的语义检索机制和用于连续认知状态跟踪的认知感知机制。认知维度捕获语义检索无法捕获的信息——用户的注意力轨迹、关注优先级和认知阶段——且这个信息可以用于连续、本地、实时处理而无需云端 API 调用。

从"有记忆的 Agent"到"有认知的 Agent"的路径需要比更好检索算法更多的东西。它需要一个独立的信号维度，捕获的不是用户说了什么而是用户如何思考。灵犀证明这在当前技术下是可行的：一个 <50ms 的本地模型、自生成的训练标签、以及使发现成为可能的完整认知架构。

未来工作将聚焦于：（1）比较有/无认知状态注入的 Agent 输出质量的端到端行为验证；（2）多用户泛化评估；（3）嵌入级注入机制以更紧密地与 LLM 推理集成；（4）扩展认知状态模型以支持主动式 Agent 行为——从"知道你在想什么的 Agent"迈向"根据所知采取行动的 Agent"。
