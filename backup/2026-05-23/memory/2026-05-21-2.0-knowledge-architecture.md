## 核心架构：大模型 + 小模型 + 规则框架 三工序流水线

```
需求 → 大模型（DeepSeek，通用语言能力，生成初稿）
     → 小模型（1.5B-3B，纯专业知识，修改纠偏）
     → 规则框架（本地 App，字数/禁用词/框架完整性终检）
     → 最终输出
```

### 小模型身份

- 不是"更懂你的大模型"，是"大模型的编辑"
- 吃初稿 + 项目上下文 → 输出修改后的文案 + 修改原因
- 基座：DeepSeek-R1-Distill-Qwen-1.5B（量化后 ~1GB）
- 训练数据：(初稿 + 上下文 → 你改完的答案) 对比对
- 冷启动 3000-5000 条，持续每周增量微调
- 用户端：Ollama 本地加载，<1 秒推理，不联网

### 训练与分发

- 训练：你的 128GB 主机，全量微调 1.5B → ~15 分钟（5000 条）
- 分发：~1GB GGUF 文件或 ~50MB LoRA adapter
- 增量更新：每周训一次 → 用户只下载更新的 ~50MB adapter

## 五层评判体系

核心原则：**不做"对错"判断，做"归属"判断**

### 第一层：身份归属（入库即执行）
```
每条修正样本标记：
  editor_id, ip_id, industry, platform, topic_type, framework, tone
不同编导的数据分开训 adapter
只有跨 IP 的行业规律才合并到行业层
```

### 第二层：自洽性校验（自动执行）
```
同一个编导、同样场景、每次改的方向是否一致
自洽样本 → 高置信度
异常样本 → 标记，等更多数据或降低权重
```

### 第三层：数据验证（发布后自动回流）
```
同一条修正模式在多条视频中的表现
vs 行业基线（同平台/同行业/同粉丝量级）
高于基线 → 1.2
基线 ±10% → 0.8~1.0
低于基线 → 0.5~0.7（风险）
严重低于基线 → 0.2~0.4（差）
```

### 第四层：跨编导共识（多编导后启用）
```
同场景多个编导都往同方向改 + 数据都好 → 行业规律
提升到行业公共 adapter，所有同行业编导受益
```

### 第五层：沙漏衰减（3.0）
```
30 天内验证有效 → 全权重
30-60 天未引用 → 降权
60-90 天未引用 → 归档
90 天+ → 重新验证（用当前热门内容测试）
```

### 完整权重公式
```
最终训练权重 = 归属匹配度 × 自洽度 × 数据验证分
```

## 多通道活性（什么算"应用"知识）

| 场景 | 活性值 |
|------|--------|
| AI 生成引用了该知识 | 基础计数 |
| 用户基于该知识做了决策（选定框架/选题/策略） | ×2 |
| 该知识匹配的项目发布了 | ×3（最高权重） |
| 用户手动查阅了该知识 | ×0.5 |
| 用户修正了该知识的产出 | 不增加活性，触发知识**更新** |

## 模块权重分配（防止固守个人知识）

```
基础知识层（行业 + 平台） → 保底 70-100%
个人适配层                → 最多 30%

实际个人权重 = 数据验证分 × 0.3

数据好的编导  → 个人层接近 30%
数据差的编导  → 个人层被压低到 10% 以下
新编导        → 降级到纯行业基线
```

## 三层评判 vs 沙漏衰减 — 正交互补

```
三层评判：这条知识"对不对"（管入）
沙漏衰减：这条知识"还有没有时效"（管出）

    数据验证高    数据验证低
最近在用  黄金样本   正在试错
很久没用  需重新验证  归档/删除
```

## Agent 记忆系统（借用同一套架构）

问题：所有 Agent 的记忆都是"更多文件"，没有遗忘机制

方案：知识库的四套理论套用过来
- 三层评判 → 什么值得记
- 沙漏衰减 → 什么该忘记
- 小模型蒸馏 → 高频记忆压缩
- 多通道活性 → 什么算"用到了"

当前可行改动：
1. MEMORY.md 加活性标记（类型 + 最后激活时间 + 引用次数 + 衰减状态）
2. 定期手动触发蒸馏（合并过时文件）
3. 严格区分"事实"和"推断"

做不到的（需改 Core）：跨 session 自动衰减、记忆加载策略底层改动
