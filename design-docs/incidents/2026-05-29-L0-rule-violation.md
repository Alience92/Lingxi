## 3. 自我诊断过程（含错误诊断）

### 3.1 我的第一轮诊断

我归结为三个"功能缺口"：

1. **消息意图分类缺失**：prefetch 没有区分"讨论"和"指令"
2. **没有"停车场"**：切线想法没地方暂存
3. **行为约束是 session 级而非 message 级**：只在 SessionStart 注入一次

### 3.2 用户纠正

用户指出了我的诊断中的逻辑问题：

- "需要在立刻做和忘掉之间二选一"→ **你没有二选一，你根本没想第三个选项。** active_context、MEMORY.md 都在，是你没想过"存下来回头再说"这条路。这不是功能缺口，是推理模式的 bug。
- "行为约束只在 session 开头注入一次"→ **这次错误发生在 session 刚开始不久，规则还在窗口里。** 不是淡出问题。
- **真正的问题不在灵犀层，不在 Claude Code 层，在模型层。** 工具都在，是模型推理时没有生成"使用工具暂存"的选项。灵犀能做的不是修模型，而是把关键规则高频注入到决策点。

### 3.3 用户指出的核心问题

**规则冲突 + 优先级缺失。** SessionStart 同时注入了：

- "信任等级L3：常规操作直接执行" → 鼓励动手
- "自主执行：直接动手继续工作" → 鼓励动手
- "动手前必须先讨论确认" → **这条不在行为约束区块里，在 MEMORY.md 的一个文件里**

第一条铁律没有被注入为强制约束，而 L3 自主执行被注入为"必须遵守"。决策时第一条的铁律就没进入注意力——不是忘了，是没有被放在能拦截行动的位置上。

## 4. 根因分层

| 层级 | 问题 | 证据 |
|------|------|------|
| **模型层** | 推理时没有生成"暂存"选项；决策树只包含"立刻做"和"忽略" | 用户指出：active_context、MEMORY.md 都可用，但模型没调用 |
| **灵犀行为层** | 铁律级约束没有被注入到行为约束区块；L3 自主执行和"先确认"之间有冲突，没有明确优先级 | SessionStart 输出：4 条行为约束都是"可以动手"，铁律在另处 |
| **模型层** | 当用户分享方向性洞察时，没有识别这不是指令而展开讨论 | 整个时间线从 #1→#2 用了不到一分钟 |

## 5. 对灵犀的启示

1. **行为约束之间可能存在冲突，目前没有冲突检测。** L3 自主执行 vs 先确认后动手——这两条规则同时存在时，模型倾向于选择更具体的、出现在行为约束区块里的那条。

2. **铁律级约束应该显式标注、不可被其他规则覆盖。** 当前的行为约束是平铺的，没有 severity 或 priority 字段，也没有"此规则不可被覆盖"的标记。

3. **MEMORY.md 里的铁律和 SessionStart 注入的行为约束是两套系统。** MEMORY.md 里的内容只在 Claude Code 的系统提示中，不在灵犀的 prefetch/SessionStart 输出里。灵犀的行为约束只来自 active_context → preferences 的分类。两套系统之间没有桥接——知道一条规则存在于 MEMORY.md 不意味着它会在决策时出现。

4. **模型的推理模式缺乏"暂停并检查规则"的内置步骤。** 在决定动手前，没有强制性的规则检查点。灵犀或许可以通过消息级注入实现——识别到"用户可能在提需求"时，前置注入铁律约束。
