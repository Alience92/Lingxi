## 二、核心判断：灵犀"双重身份"问题

**灵犀系统当前同时是两样东西：**

1. **记忆服务**（DSH 里运行的 engine + adapter + 检索/分片/衰减/蒸馏）——这是"记忆"的本质
2. **陪伴者对话 Agent**（api/server + chat-engine + persona + affinity + reflection + life-state + web-search + 手机壳服务）——这是"会说话、有性格的 AI 伴侣"

两条线通过 `engine.ts`（记忆）和 `index.ts`/`api/server.ts`（对话）**松散共存**，共用同一个 `memory.db` 和灵络图，但**面向完全不同的使用场景**。

**用户的诉求（"很多功能都不是基于记忆功能服务的"）指向：把 2 从 1 中剥离/简化，让记忆服务成为单一、清晰的核心。**

## 三、简化设计（方案）

### 方案核心：双层结构 — 记忆核心 vs 可选认知层

```
┌─────────────────────────────────────────────────┐
│  灵犀记忆服务（精简核心）                          │
│  engine.ts ← system-controller.ts（整体层）       │
│  ├─ 写入：fragmenter（四通道分片）→ state-gate    │
│  ├─ 存储：db（fragments/anchors/links/FTS/向量）  │
│  ├─ 检索：memory-recall（灵络+字图+认知向量+FTS） │
│  ├─ 维护：orchestrator（沙漏/衰减/蒸馏/dreaming） │
│  └─ 查询：health + status                        │
│  ── DSH Adapter：search/remember/status          │
└─────────────────────────────────────────────────┘
        │
        ▼ 可选层（默认关闭/独立进程）
┌─────────────────────────────────────────────────┐
│  灵络认知图（记忆增强，非对话）                    │
│  dcgk-*（行为决策路由，供检索融合）               │
└─────────────────────────────────────────────────┘
        │
        ▼ 独立产品线（移出记忆服务，单独部署）
┌─────────────────────────────────────────────────┐
│  陪伴者对话系统（BYOC server）                    │
│  api/server + chat-engine + persona + affinity   │
│  + reflection + life-state + web-search + ...    │
└─────────────────────────────────────────────────┘
```

### 具体动作

#### 1. 记忆核心瘦身（推荐执行）
- **保留**：A 组全部 + system-controller + engine
- **灵络 7 文件**：建议**保留但标记为"认知增强层"**，从 orchestrator 主链剥离（当前 orchestrator 只在 review 阶段条件调用 lingluoDreaming——已经是可选路径）。若追求极致精简，可整体移入 `src/cognitive/` 子目录，默认不加载

#### 2. 陪伴者功能移出（推荐执行）
- 将 C 组 18 个文件（约 3300 行）从 `src/core/` 和 `src/` 移入 **`src/companion/`** 独立子目录（或独立 npm 包 `lingxi-companion`）
- `index.ts`（BYOC 启动）与记忆服务解耦——启动记忆服务不再拉起对话服务
- DSH 侧只保留记忆工具，不暴露陪伴者 API

#### 3. 明确"记忆服务"边界（核心动作）
- **对外接口收敛为 5 个**：`remember`（记）、`search/recall`（取）、`maintain`（维护）、`status`（状态）、`ingestSignal`（信号）
- 所有记忆能力通过 engine + system-controller 暴露，**不再有第二入口**
- 陪伴者若要使用记忆，通过同一 engine 接口（而非直接操作 DB）

#### 4. 工具脚本归档
- 保留 eval（记忆评测）
- 人格训练数据脚本（generate-persona-* 等）随陪伴者线移出
- 转换脚本保留
